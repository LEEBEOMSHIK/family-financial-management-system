# 내 계좌 및 출금 증빙 운영 안내

요구사항 R04·R05·R18. 사용자가 확정한 두 요청 유형은 사용 후 정산(영수증 필수)과 사용 전 선지급(사유 필수, 영수증 사후 제출)이다. 출금 승인 자체는 송금 실행이나 잔액 차감이 아니다.

## 사용자 흐름
1. 본인 계정으로 로그인하고 **내 계좌**에서 은행명·예금주·계좌번호와 별칭을 등록한다. 기본 계좌를 지정한다.
2. **출금 요청**에서 정산/선지급을 선택한다. 기본 계좌가 미리 선택되며 등록한 다른 계좌로 변경할 수 있다.
3. 사용 후 정산은 영수증을 첨부해야 제출된다. 선지급은 사용 목적을 설명해 제출하고, 승인 전후에 실제 영수증을 추가할 수 있다. 반려된 요청에는 추가하지 않는다.
4. 검토자는 요청의 지급 계좌와 영수증 미리보기를 확인한다. 승인 당시의 증빙 집합은 기록으로 고정하며 나중에 추가한 영수증과 구분한다.

계좌는 사용자별로 분리된다. 기본 계좌 변경은 새 요청에만 적용된다. 이미 제출한 요청의 계좌 ID와 내용은 변경하지 않는다. 계좌번호를 수정하려면 새 계좌로 등록한다. 은행 실명조회·계좌 유효성 검증·자동 송금은 제공하지 않는다.

2026-10-25 추가: 승인된 요청은 송금 대기로 표시한다. 현직 총무가 은행 앱에서 실제 송금한 후 상세의 실제 송금일·메모·전액 송금 확인을 입력해 송금 완료를 기록한다. 처리자·기록 시각을 보존하며 은행 대사·원장 차감은 수행하지 않는다. 총무가 승인하면 카카오톡 알림을 생략하고, 그 외 승인 시 알림 대기 이벤트를 저장한다. 실제 카카오 발송은 아직 미연동이다. [송금 완료 및 알림 인수인계](../plans/payment-completion.md)를 따른다.

## 암호화 및 복구
계좌번호와 영수증 원본/미리보기는 서버의 Fernet 인증 암호화를 사용한다. `FINANCIAL_DATA_KEY`는 API 전용 환경변수이며 웹 공개 변수에 넣지 않는다. 로컬 실행기는 Git 제외 `var/secrets/financial-data.key`를 읽는다. 키는 DB 또는 DB 덤프에 저장하지 않는다.

최초 설치에서는 **004 마이그레이션 적용 전에** 아래 명령을 실행한다.

```powershell
& apps/api/.venv-pg/Scripts/python.exe scripts/setup_financial_key.py
```

기존 키는 덮어쓰지 않는다. 004 적용 이후 키 파일이 없어지면 자동 재생성을 거부한다. 키를 바꾸면 기존 암호문을 읽을 수 없으므로 원래 키를 복구해야 한다. DB 백업과 별도로 암호화 키를 안전한 비공개 위치에 백업하고 접근자를 제한한다. 현재 도구에는 무중단 키 회전 기능이 없다.

`scripts/backup_database.py --verify-restore`는 원래 FINANCIAL_DATA_KEY를 비공개로 주입받아 새 임시 DB에 복원하고 전체 테이블 내용·금액 합계·암호문 복호화·원본 해시를 비교한다. 성공 기록은 비공개 백업 폴더에 남긴다. 암호화 키가 빠진 DB 덤프만으로는 계좌·증빙을 복호화할 수 없다. 실제 복구는 별도 DB에 복원하고 원래 키를 API에 제공하여 로그인·요청·증빙 미리보기를 확인한 후 연결을 전환한다. 원본 DB를 삭제하거나 덮어쓰지 않는다.

## 이미지 취급
지원 형식은 JPG·PNG·WebP, 파일당 최대 6MiB, 요청당 최대 5개다. PDF·HEIC·동영상·애니메이션은 현재 지원하지 않는다. 서버에서 실제 형식, 픽셀 수와 디코딩 가능 여부를 검증하고 메타데이터를 제거한 PNG 미리보기를 생성한다. 원본은 암호화하여 보존하며 직접 공개하지 않는다. 미리보기에도 서버의 가족·요청·소유자 권한을 적용한다.

형식 검증·재인코딩은 외부 악성코드 백신 검사를 수행했다는 뜻이 아니다. 공개 운영 전 업로드 처리량 제한, 외부 백신/격리 운영, 보관·폐기 정책과 키 관리 운영 체계를 검증해야 한다. 실제 영수증과 계좌번호를 로그·스크린샷·공개 이슈·Git에 남기지 않는다.

## 기술 선택 근거
- [Cryptography Fernet](https://cryptography.io/en/stable/fernet/): 인증된 대칭 암호화와 키 보관 요구사항.
- [Pillow 보안 안내](https://pillow.readthedocs.io/en/stable/handbook/security.html): 형식 제한, 바이트/픽셀 크기 제한과 압축 폭탄 방어.
- cryptography 50.0.2, Pillow 13.0.0 및 전이 의존성은 requirements.lock에 고정하고 공식 라이선스·버전 메타데이터는 dependency-metadata.json에 기록한다.

실제 변경 파일, 검증 결과와 남은 범위는 [구현 계획 및 기록](../plans/accounts-evidence.md)을 따른다. 2026-10-24 사용자가 총무 또는 총괄관리자 1인 처리, 총무 요청은 총괄관리자 처리, 실제 송금은 총무가 별도로 수행하는 규칙을 확정했다. 자기 처리 금지는 유지한다. 로컬 DB에는 `scripts/activate_expense_policy.py`로 확정 정책을 새 이력으로 기록했다. 신규 환경에서만 동일 명령이 필요하며 이미 기록된 버전을 덮어쓰지 않는다. 정책이 없는 별도 환경은 계속 승인/반려를 거부한다.
