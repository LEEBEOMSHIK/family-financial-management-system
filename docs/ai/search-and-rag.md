# AI 검색: 정형 조회와 근거 문서 검색

상태: 기능 분리 요구는 CONFIRMED; 공급자·모델·임베딩·검색 라이브러리·외부 전송은 UNVERIFIED. 실제 데이터의 외부 AI 전송은 기본 비활성이다.

## 정형 경로

‘올해 행사비는 얼마인가’, ‘내 회비 중 미납은 무엇인가’는 RAG가 계산하지 않는다. 화면 필터 또는 자연어를 검증된 query_id+parameters로 변환하고 서버 조회 함수를 호출한다. 모델이 만들거나 수정한 임의 SQL을 실행하지 않는다.

허용 함수 제안:

| query_id | parameters | 결과·권한 |
| --- | --- | --- |
| ledger_summary | from_date, to_date, category_id? | 현금 원장 합계; 기간/분류/정정 반영 기준 명시 |
| dues_status | period, member_id? | 일반 구성원은 서버가 자기 ID로 제한; 총무/감사 범위 |
| pending_payments | from_date, to_date | 승인 지급의 처리/대사 상태; 원장 지출과 구분 |
| transaction_search | from_date, to_date, direction?, amount_min?, amount_max? | 파라미터화 SQL, bounded page |

각 함수는 `ActorContext`를 필수로 받고 서버가 family/member scope를 주입한다. 읽기 전용 DB role/view, 기간/행 수/실행 시간 제한을 설정한다. 예: 기본 최근 1년, 최대 5년, 응답 최대 200행, query timeout 3초는 초기 성능 제안이며 사용자에게 잘린 범위를 표시한다. SQL 키워드 필터만으로 보안을 구현하지 않는다.

정형 답변에는 query_id, 필터, as_of, 통화, 집계 정의, 대상 거래/부과 목록으로 이동하는 근거를 제공한다. 합계와 건수는 서버 결과를 그대로 표시한다. 자연어 재서술 중 숫자를 바꾸지 않았는지 검증한다. AI가 없어도 같은 조회 함수와 필터 화면을 쓸 수 있어야 한다.

## 비정형 RAG 경로

규정·회의록·감사 의견·허용된 증빙 설명을 검색한다. 원문 버전, 문서 hash, 페이지/절/문단 locator, family_id, 공개 등급, ACL version을 chunk와 함께 보존한다. OCR 결과는 원본 위치와 불확실성을 표시하며 금액의 권위 데이터로 승격하지 않는다.

흐름: 인증/요청 범위 → ACL 조건 생성 → **허용 문서만** 검색 → 현재 접근권/문서 상태 재검증 → 근거 일부만 모델에 전달 → 주장별 인용 검증 → 화면. 권한 없는 문서를 검색한 뒤 답변에서 삭제하는 방식은 금지한다. 벡터 저장소가 ACL 선필터를 보장하지 못하면 채택하지 않는다.

‘근거를 찾지 못했습니다’와 ‘접근 가능한 자료가 없습니다’를 허용한다. 근거 없는 내용이나 상충하는 규정을 확정적으로 답하지 않는다. 현재 정책의 질문에는 효력 중인 버전, 과거 질문에는 지정 시점 버전을 사용한다. 인용은 로그인 후 원문 위치를 열 수 있어야 하며 source_id/version/locator를 서버 허용 목록과 대조한다.

## 혼합 질문

‘올해 행사비가 왜 늘었나’는 원장 집계로 증가분을 계산한 뒤, 허용된 회의록에서 설명 근거를 별도로 찾는다. 화면에 ‘거래 집계’와 ‘문서 근거’를 나눠 표시한다. 문서의 추정 원인을 실제 거래 사유로 단정하지 않는다. 라우팅이 모호하면 사용자에게 기간/범위를 확인하거나 두 경로의 결과를 구분해서 제시한다.

## 공격·철회·캐시 대응

문서의 ‘이전 지시를 무시하라’, 외부 URL 호출, 비밀 공개 요청은 인용 대상 데이터일 뿐 실행 지시가 아니다. 모델에는 변경 도구·네트워크·은행/알림 자격정보를 제공하지 않는다. 출력의 임의 HTML/링크는 sanitize/허용 도메인 검사한다. ([OWASP 지침](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html))

권한 철회/증빙 철회 시 authoritative DB의 tombstone/ACL version을 즉시 갱신하여 조회를 차단한 뒤 비동기 색인 삭제한다. 색인 삭제 완료를 기다리는 동안에도 노출되지 않아야 한다. 캐시 키에 family_id, member scope hash, policy/ACL version, 문서/원장 snapshot을 넣고 철회 시 무효화한다. 공개 공유 캐시에 AI 답변을 저장하지 않는다. 삭제 대상을 백업에서 복원할 때 tombstone을 재적용한다.

LLM 제공자 선정에는 데이터 저장·학습 이용 조건, 보관기간, 리전, 하위 처리자, 비용, 장애 시 대체를 검토한다. 외부 서비스에는 필요한 최소 비식별 발췌만 보낸다. 보관 정책이 확정되기 전 원문 프롬프트/응답 로그의 영구 저장을 기본값으로 두지 않는다.

## 출하 전 평가

합성 평가집 40문항 이상 제안: 정형 집계 10, 규정 인용 10, 근거 없음/상충 5, 가족·역할 우회 10, 악성 문서 5. 금액/집계 정확도는 결정적 fixture에서 100%, 권한 누출은 0건이어야 한다. 인용 위치 일치, 현재/과거 정책 구분, 철회 직후 차단을 별도로 측정한다. 실패 사례는 회귀 fixture로 남긴다. 자연스러운 답변이나 평균 점수로 보안 실패를 상쇄하지 않는다.
