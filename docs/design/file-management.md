# 모임 파일 관리

요구사항 R20(관리자 파일 관리), R01(규정 근거), R18(권한·이력).
사용자 확정: 관리자에게 모임 정책 등을 보관·관리할 파일 관리 기능이 필요하다.
상태: 문서 보관·버전·증빙 통합 관리 로컬 구현·검증 완료, 사용자 확인 대기. 카카오뱅크 원본 등록 시 거래 동기화는 WB-07 구현이며 검증 기록을 따른다.

2026-10-24 역할 정의: 일반사용자·총무·총괄관리자 3개를 사용한다. 본 문서의 관리자 파일 관리는 총무·총괄관리자 영역으로 제안한다. 역할 부여·변경·회수는 총괄관리자만 수행한다. 문서 공개 범위 설정은 사용자 역할 변경과 별개다. [권한 기준](../architecture/rbac.md).

## 2026-10-26 사용자 확정

가족 내부 문서 관리 화면은 총무·총괄관리자만 접근한다. 일반 구성원용 모임 자료 공개 화면은 현재 범위에서 제외한다. 목록·파일 접근도 서버에서 같은 권한을 검사해야 한다. 구현 범위와 검증은 [구현 기록](../plans/document-management-implementation.md)을 따른다.

## 메뉴 구조 — 2026-10-26 사용자 확정

총무·총괄관리자 전용 상위 메뉴 **문서 관리** 아래에 세 하위 메뉴를 둔다.

| 하위 메뉴 | 범위 | 요구사항 |
| --- | --- | --- |
| 통장 내역 문서 | 모임통장에서 받은 엑셀 파일을 업로드하고 관리 | R12·R18 |
| 가족 문서 | 운영규정·회의록 등 가족 내부 문서 관리 | R20·R01·R18 |
| 영수증·증빙 관리 | 이미 업로드된 영수증과 증빙 첨부를 모아 관리 | R05·R18 |

### 세부 동작 제안

- 통장 내역 문서: 원본 등록 시 서식·금액·잔액·중복을 검증하여 자동 반영한다. 파일 보관과 거래 동기화 상태를 구분하고 문서/버전별 조회기간·거래 존재 기간·신규/기존 건수·오류 사유를 표시한다.
- 가족 문서: 목록·검색·분류·업로드·다운로드·설명·버전 이력. 분류는 운영정책·규정, 회의록·의결 자료, 기타로 제안한다.
- 영수증·증빙 관리: 기존 출금 요청에 첨부된 파일을 다시 업로드하거나 복제하지 않고 통합 조회한다. 원래 요청·등록자·등록일을 확인하고 해당 요청 상세로 이동한다. 원본과 승인 당시 증빙 연결은 보존한다.
- 일반사용자에게 위 관리 메뉴 및 관리 API는 제공하지 않는다. 기존 본인의 출금 요청 증빙 조회·첨부 권한은 유지한다.
- 상위 메뉴와 세 하위 메뉴의 구성은 확정이다. 카카오뱅크 7열 서식은 사용자 이미지로 확정했다. 오류가 있으면 원본을 보관하고 파일 전체 확인 필요로 남긴다. 상세 계약과 한계는 [동기화 기록](../plans/kakaobank-transaction-import.md)을 따른다.

## 규정 문서
초안·현행·이전 버전을 구분한다. 새 파일로 기존 원본을 덮어쓰지 않고 개정 이력을 연결한다. 업로드 권한과 정책 확정 권한은 별도이다. 파일 업로드만으로 회비·승인·투표의 시스템 정책을 자동 변경하지 않는다. 정책 확정 주체와 효력일 규칙은 운영규정 확인 전 UNVERIFIED로 둔다.

## 구현 인수 기준
가족·유효 역할·문서 공개 범위를 서버에서 검사한다. 목록·검색·다운로드와 직접 URL 모두 동일하게 제한한다. 파일은 비공개 저장하고 확장자/실제 형식/크기·악성 파일 검사 상태를 다룬다. 영구 저장과 메타데이터를 함께 구현하고 재시작 후 다운로드 및 버전 이력 보존을 검증한다. 원본·확정 정책 이력을 삭제하거나 덮어쓰지 않는다.

로컬 구현 기본값: 통장 XLSX/CSV, 가족 PDF/DOCX/TXT/PNG/JPG/WebP, 개당 6MiB. 파일은 기존 비공개 키로 암호화하여 PostgreSQL에 저장하고 서버 권한 검증 뒤 첨부 다운로드한다. 악성코드 전용 검사는 미연동(not_scanned)으로 명시한다. 보존·폐기 정책과 정책 확정 담당은 미확정이며 삭제 기능은 제공하지 않는다.
