# 가족 장부 디자인 시스템 v0.2

상태: PROPOSED · ‘가족 장부’는 작업용 표시명이다. 브랜드명은 확정되지 않았다.

2026-10-24 공통 앱 개선: 시스템 글꼴을 유지하면서 메뉴 16px·표 본문 15px·거래 제목 16px·주요 잔액 32~44px로 위계를 분리했다. 중립 카드 12~14px, 공통 입력/버튼 9px, 명확한 선택 메뉴와 현재 계정 역할 표시를 적용했다. 실제 앱의 최신 시각 조정은 `workspace.css`와 [변경·검증 기록](../plans/workspace-style.md)을 따른다. 아래 이전 배치의 6px 카드 기준은 최신 앱에 적용하지 않는다.

2026-10-23 사용자 레퍼런스 반영: 실제 앱은 고정 좌측 메뉴·상단 필터·표 중심의 업무형 배치를 적용했다. 브랜드 색상은 유지하며 앱 구획은 6px 모서리와 16~20px 간격으로 정돈한다. 셀렉트 옵션에도 동일 토큰을 사용한다. 모바일 탐색은 접히는 메뉴다. 기존 정적 HTML은 이전 시안이며 최신 화면은 실행 앱에서 확인한다. [변경 파일·검증·한계](../plans/dashboard-refinement.md).

## 브랜드 방향

신뢰는 장식보다 출처·기준 시각·정확한 상태에서 나온다. 화면의 우선순위는 **지금 확인할 일 → 금액과 상태 → 근거 → 다음 행동**이다. 사용자 지정 핑크 #FF849E와 블루 #6492DB를 브랜드 색으로 사용한다. 기본 화면·카드·일정·아이콘은 흰색과 중립색으로 구성한다. 원색은 작은 브랜드 표시와 수입·지출 비교 차트 및 해당 범례에 한정한다. 일반 링크는 중립색으로 표시하고 주요 행동에만 진한 블루 #315FA8을 제한적으로 사용한다. 은행 로고/브랜드처럼 보이게 만들지 않는다. 넓은 여백, 정렬된 숫자, 짧고 분명한 한국어를 쓴다. 지나친 그라데이션·반짝임·성공 애니메이션을 피한다.

## 토큰과 적용

실제 앱 가독성 기준(사용자 피드백 반영): 본문·콤보박스 선택값·옵션 16px, 필터 라벨·표 본문 14px, 보조 설명 최소 13px, 구획 제목 18px. 모바일에서도 작은 글자로 축소하지 않는다. 앱의 작은 글자는 rem 단위를 사용한다. 입력 높이 48px, 거래 행 최소 76px(모바일은 내용 높이)을 확보하고 폭이 부족하면 줄바꿈/세로 배치한다. 차트 월 라벨은 SVG 축소에 따라 작아지지 않는 HTML 텍스트로 표시한다.

원본은 `tokens.json`, CSS 결과는 `apps/web/src/styles/tokens.css`이다. 변경 시 함께 갱신하고 `scripts/validate_foundation.py`로 일치/대비를 확인한다. 전역 CSS와 예제 컴포넌트는 라이브러리 없이 Next.js에 가져올 수 있다. Tailwind, shadcn/ui, Radix, 폰트 패키지는 아직 선택하지 않았다.

## 접근성

WCAG 2.2 AA를 목표로 한다. 일반 텍스트 대비 4.5:1, 큰 텍스트 3:1, 의미 있는 UI 경계/아이콘 3:1을 기준으로 확인한다. 터치 대상은 자체 기준 44×44px을 적용한다(AA의 Target Size Minimum 24px보다 넉넉한 설계 목표). 준수 인증이나 전체 평가 완료를 뜻하지 않는다. ([WCAG 2.2](https://www.w3.org/TR/WCAG22/))

skip link, 한 개의 h1, 논리적 heading, landmark, label과 input 연결, 오류의 aria-describedby, 저장 결과의 polite live region을 제공한다. 색상만으로 수입/지출·성공/실패를 구별하지 않는다. 키보드 포커스가 sticky 영역에 가려지지 않게 한다. dialog는 포커스 이동/가두기/닫기/복귀, table은 caption·scope·정렬 상태를 갖춘다. 아이콘 단독 버튼에는 접근 가능한 이름과 tooltip을 제공한다.

320 CSS px에서 본문/폼은 수평 스크롤 없이 보인다. 표는 카드 전환 또는 명시적 횡스크롤 영역으로 제공하며 금액·상태·날짜를 삭제하지 않는다. 200% 글자 확대, 400% 줌의 재배치, 고대비/강제색상, reduced-motion을 검증한다. 로딩 skeleton은 읽기 순서를 방해하지 않고 실제 label을 유지한다.

## 반응형

- <768px: 1열, 카드 여백 16, navigation은 메뉴/직접 링크 패턴. 폼 label은 위쪽. 핵심 행동은 읽기 순서 안에 배치한다.
- 768~1023px: 2열 요약, 리스트+상세는 별도 페이지 또는 충분한 폭의 drawer.
- ≥1024px: 좌측 탐색, 3열 요약, 테이블+필터. 주요 본문 최대 1200px.
- 입력/버튼은 줄바꿈을 허용한다. sticky footer 사용 시 여백과 safe area를 확보하고 오류 요약을 가리지 않는다.

## 핵심 컴포넌트 계약

### 처리할 일이 있는 카드의 강조 (2026-10-25)

대시보드의 개별 송금 항목(`.payment-task-link`)과 출금 요청 목록의 송금 대기 카드(`.expense-item[data-payment-pending=true]`)에 마우스를 올렸을 때 `task-active-border` 토큰으로 밝은 녹색 테두리를 표시한다. 내 할 일 전체 영역에는 적용하지 않는다. 라이트 `#86D9A0`, 다크 `#5CBF85`. 링크는 2px inset, 기존 테두리가 있는 카드는 테두리 색 변경과 1px inset으로 크기·배치 변화 없이 강조한다. 기기 감지 미디어 쿼리로 제한하지 않고 실제 :hover 상태에 적용하며 포인터가 벗어나면 사라진다. 터치·혼합 입력 환경에서 hover:none으로 감지되어도 포인터 hover를 차단하지 않는다. 승인 대기·반려·송금 완료 카드에는 적용하지 않는다. 완료 상태를 의미하지 않으며 키보드 포커스는 기존 포커스 토큰을 유지한다.

### 문서 업로드 화면과 파일 선택 (2026-10-26)

문서 목록과 등록 폼은 별도 화면으로 제공한다. 목록의 ‘문서 업로드’와 ‘새 버전’에서 전용 업로드 화면으로 이동하며, 저장 성공 시 목록으로 돌아간다. 복귀 버튼과 제목은 기존 공통 24px 간격을 따른다.

- 기본 파일 입력을 그대로 노출하지 않고 점선 테두리의 파일 선택 영역을 제공한다. PC에서는 드래그 앤 드롭, 모든 기기에서는 클릭·키보드 선택을 지원한다.
- 영역 안에 업로드 아이콘, 드래그 안내, 클릭 선택 안내, 허용 형식·파일 개수·용량을 표시한다. 드래그 중에는 정보색 배경과 테두리로 강조하며 키보드 포커스는 별도로 유지한다.
- 선택한 파일명·크기·형식과 변경/제거 버튼을 표시한다. 잘못된 선택은 안내하고 이전 유효 선택을 보존한다. 폴더·여러 파일·지원하지 않는 형식·초과 용량을 검증한다.
- 업로드/결과 확인 중 파일과 메타데이터를 고정해 중복/다른 파일 재시도를 방지한다. 서버 검증을 클라이언트 검증으로 대체하지 않는다.
- 파일 영역→선택 정보 16px, 주요 폼 구획 24px, 영역 내부 12px를 기존 토큰으로 적용한다. 모바일에서도 파일명은 줄바꿈하고 버튼은 접히지 않도록 재배치한다.

### 검색·결과 안내·목록 간격 (2026-10-26)

검색 화면은 **검색/필터 영역 → 결과 건수 안내 → 목록 또는 빈 상태** 순서로 배치한다. 검색창과 결과 안내가 붙어 보이지 않도록 브라우저 기본 p 여백에 의존하지 않는다.

| 관계 | PC·모바일 공통 기준 | 구현 |
| --- | --- | --- |
| 앞선 콘텐츠 → 검색 영역 | 24px | `--space-6` |
| 검색 영역 하단 → 결과 건수 안내 | 16px | `.list-result-summary` 상단 `--space-4` |
| 결과 건수 안내 하단 → 목록/빈 상태 | 16px | `.list-result-summary` 하단 `--space-4` |
| 검색 영역 내부 입력·버튼 사이 | 12px | `--space-3`, 줄바꿈 시에도 유지 |

결과 0건·검색 결과 없음·데이터 있음에서 동일하게 적용한다. 모바일과 다크모드에서도 간격을 줄이지 않는다. 새 목록 화면은 공통 `.list-result-summary`를 재사용하고 검색창·건수·목록의 실제 경계 간격을 확인한다. 문서 관리의 세 하위 화면에 적용했다.

### 상세 화면의 복귀 탐색과 간격 (2026-10-25 적용)

상세 화면은 **복귀 버튼 → 제목 영역 → 상세 콘텐츠** 순서로 배치한다. 복귀 버튼을 제목 텍스트에 바로 붙이지 않는다. `BackButton` 공통 컴포넌트와 `.page-back-navigation`을 사용하고 화면별 임의 여백을 추가하지 않는다.

| 관계 | 공통 기준 | 구현 |
| --- | --- | --- |
| 복귀 버튼 하단 → 제목 영역 시작(상단 보조 문구 포함) | PC·모바일 모두 24px | `--space-6`, wrapper margin-bottom |
| 왼쪽 화살표 → 버튼 문구 | 8px | `--space-2`, inline-flex gap |
| 복귀 화살표 | 18×18px, currentColor | 왼쪽 방향 SVG, 장식용 aria-hidden, 텍스트 ‘목록으로’ 유지 |
| 세로 폼의 라벨 → 콤보박스 | 8px | 공통 select-field gap; 폼 전체 항목 간격과 구분 |
| 상세 정보 섹션 사이 | 구분선 + 24px 여백 | 요청 내용·지급 계좌·증빙의 시각적 경계 |

제목 영역 내부는 기존 `.page-title`/`.eyebrow` 공통 스타일을 따른다. 복귀 버튼은 공통 버튼 높이·포커스·비활성 스타일을 사용한다. 다크모드에서도 동일 간격이며 색은 기존 토큰을 상속한다. 새 색상이나 간격 토큰은 추가하지 않았다.

| 컴포넌트 | 내용/행동 | 필수 상태·접근성 |
| --- | --- | --- |
| Button | primary/secondary/danger/ghost, pending | type 기본 button, 중복 제출 방지, busy·disabled 이유 |

| EvidenceUploader | 선택→격리→검사→첨부 | 크기/형식 사전 안내, 진행/실패/교체 이력 |

현재 TSX 예제는 Button, Money, StatusBadge만 제공한다. 나머지는 계약이며 구현 완료 컴포넌트로 표시하지 않는다. 복잡한 dialog/calendar는 검증된 접근성 라이브러리를 후보 평가한 뒤 사용한다.

## 화면 패턴

1. **대시보드:** 기간/기준시각 → 잔액(출처)·승인 예정액·미처리 건 → 오늘 할 일 → 최근 거래. 잔액 조회 실패는 마지막 확인값+실패 안내 또는 ‘확인 필요’.
2. **원장:** 기간·분류 필터 → 합계/범위 → 거래 표(날짜, 내용, 입금, 출금, 대사) → 상세 근거. 필터 결과가 전체 잔액과 다른 이유를 설명한다.
3. **지출 상세:** 제목/상태/금액 → 요청 내용·증빙 → 승인 이력 → 지급 일정 → 송금 기록 → 대사. ‘송금하기’ 버튼 대신 ‘송금 내역 기록’을 쓴다.
4. **파일 가져오기:** 파일 선택 → 열 매핑 → 오류/중복 검토 → 반영 확인 → 결과. 반영 전 총합·행 수·계좌·기간을 확인한다.
5. **연간 일정:** 연도 선택 → 행사/송금 날짜 구분 → 지급 승인 상태 → 알림 계획. 색만 있는 캘린더 대신 읽을 수 있는 목록을 함께 제공한다.
6. **감사:** 미대사·증빙 누락·정정 목록 → 근거 비교 → 의견/답변 → 확인 이력. 원장 편집과 감사 확인을 분리한다.
7. **투표:** 안건·규정/유권자 기준·마감 → 선택 → 제출 상태 → 공개 정책에 따른 결과. 사용자 선택을 audit log에 무조건 남기지 않는다.
8. **검색:** ‘거래·회비 조회’와 ‘규정·문서 검색’ 모드를 구분. 정형 결과는 필터/기준시각, 문서 답변은 근거·버전·불확실성을 표시한다.

## 2026-10-23 공통 대시보드 시안 인수인계

요구사항: R03/R06/R12/R18/R19. 사용자 지정 브랜드 색, 가족 공통 이용, 권한별 관리 메뉴, PC·모바일웹 우선, 자금 흐름 대시보드를 반영한다. 향후 앱은 검토 대상이다.

검토 방향: 할 일 우선은 업무 처리에, 현황 우선은 가족 전체의 자금 이해에, 소식 우선은 가족 소통에 유리하다. 대화에서 합의한 공통 대시보드에 따라 잔액·수입·지출을 먼저 배치한다. 모바일에서는 차트보다 내 할 일을 먼저 제공한다.

`preview.html`은 가상 데이터 기반 검토용 시안이다. 가족/관리 화면 전환은 비교용이며 인증이나 권한 구현이 아니다. 실제 서비스는 서버 capability로 관리 항목과 자료 접근을 판정해야 한다. 관리자는 새로운 업무 역할을 뜻하지 않으며 현직 총무·감사 등 확정 권한별로 기능을 구분한다. 공개 범위는 규정 확정 전 UNVERIFIED다.

현재 잔액과 지급 예정액을 분리하고, 기간 전환으로 수입·지출·차트·분류·거래를 함께 변경한다. 잔액은 선택 기간과 독립된 최신 확인값이다. 차트에는 텍스트 표를 제공한다. 미연결/조회 실패를 0원으로 대체하지 않는다.

수정 파일: 이 문서, tokens.json, 공통 tokens.css, preview.html, dashboard.css, dashboard.js, ADR-0006, 검증 기록. API·DB 계약 변경 없음. 후속 제품 구현은 화면 피드백 후 진행하며 실제 권한·은행·알림 연동은 별도다.

## 노란색 및 다크모드 요구사항 — 2026-10-23

R19 확장: 사용자가 노란색 추가와 다크모드 지원 준비를 요청했다. 노란색의 정확한 값은 지정하지 않아 `#F2C75C`를 제안 토큰 `brand-yellow`로 추가했다. 핑크·블루와 동일하게 불필요한 카드 배경이나 장식에 반복하지 않는다. 브랜드 노란색은 warning 상태 토큰과 별개이며, 노란색만으로 주의/미처리를 표현하지 않는다. 현재 대시보드에 사용 목적이 없는 노란 장식은 추가하지 않았다.

다크모드 요구는 확정이며 다음 세부 동작은 구현 기준 제안이다.

- 선택: 시스템 설정 따르기(기본), 라이트, 다크. 시스템 선택 시 OS 테마 변경을 반영한다.
- 명시적 선택을 기기에 기억한다. 저장소가 차단되어도 화면과 전환이 동작해야 한다.
- 배경·카드·본문·보조 글자·경계·링크·상태·포커스를 의미 토큰으로 분리하고 라이트/다크 값을 각각 검증한다. 브랜드 원색을 다크 배경에 기계적으로 그대로 적용하지 않는다.
- 차트·표·입력·드롭다운·빈 상태·오류 상태·모바일 메뉴까지 테마를 적용한다. 첫 로드의 밝은 화면 깜박임과 서버/브라우저 초기 테마 불일치를 점검한다.
- PC/모바일에서 양쪽 테마의 가독성, 키보드 포커스, 확대를 확인한다. 색상에만 의존하지 않는다.

현재 구현 상태: 노란색 토큰, 라이트/다크 의미 토큰, 시안의 시스템·라이트·다크 전환과 기기별 설정 기억을 구현했다. 시스템 변경과 다른 탭의 설정 변경을 반영하며 저장 차단 시 현재 화면에서 전환할 수 있다. 현재 preview.html은 대시보드와 공통 디자인 검토용이며 다른 기능 화면 구현 완료를 의미하지 않는다.

### 역할별 내 할 일 영역

총괄관리자는 승인 대기, 총무는 승인 대기·송금 대기를 별도 테두리 영역으로 표시한다. 영역 제목·건수·대기 금액과 빈 상태를 항상 유지한다. 두 영역은 세로로 배치하고 간격은 20px, 카드 안쪽 좌우 여백은 16px이다. 승인 요청 hover는 primary, 송금 요청 hover는 task-active-border 토큰을 사용한다. 제목과 다음 동작(요청 검토/송금 처리)으로 의미를 구분하며 색에만 의존하지 않는다.

### 내 계좌 카드

계좌 목록은 출금 요청의 compact 목록 스타일과 분리한다. 동일 그리드의 카드 높이는 grid-auto-rows:1fr와 stretch로 통일하고, 하단 동작은 margin-top:auto로 정렬한다. 카드 여백 PC 24px/모바일 20px, 카드 간격 20px/16px, 제목은 최소 두 줄 공간을 확보한다. 은행·계좌번호·예금주를 라벨/값으로 구분한다. 기본 계좌 지정 버튼과 기본 계좌 상태 표시는 같은 44px 높이를 차지한다. 기본 계좌에는 primary 테두리·아이콘과 텍스트 체크 표시를 사용한다. 전체 계좌번호는 기존의 명시적 확인 동작 전까지 마스킹한다. 긴 텍스트는 줄바꿈하며 고정 높이로 잘라내지 않는다.

### 사용자별 대시보드 위젯

대시보드 편집에서만 이동/크기/표시를 변경한다. PC는 2열 격자, 반폭·전체폭과 작게(280px)·보통(420px)·크게(560px)의 크기를 사용하며 순서대로 배치한다. 모바일은 한 열·높이 자동이며 순서/표시를 별도 저장한다. 포인터 이동 손잡이와 앞/뒤 버튼, 크기 손잡이와 크기 선택 메뉴를 함께 제공한다. 긴 내용은 PC 위젯 내부에서 스크롤한다. 편집 중 위젯 내부 업무 링크·버튼은 비활성화하고 조회 기간도 잠근다. 저장/취소를 구분하며 기본 복원은 현재 편집 기기의 초안만 바꾼다. 권한 없는 위젯은 목록에서 제외하고 서버 저장에서도 거부한다. 크기·간격·색은 공통 토큰을 사용한다.

### 제목 영역의 주요 동작 간격 (2026-10-26)

제목·설명 묶음과 주요 동작은 `.page-title.page-title-with-actions`로 배치한다. 넓은 화면에서는 좌우 배치하고, 공간이 부족하면 동작을 다음 줄로 내린다. 두 묶음 사이 가로·세로 간격은 `--space-5`(20px)로 유지한다. 기존 `.expense-title`과 동일한 공통 배치다. 일반 `.page-title`만 사용하면 형제 버튼과의 간격을 제공하지 않으므로 주요 동작이 있는 화면에서 단독 사용하지 않는다. 라이트·다크·320px에서도 줄바꿈 후 간격과 버튼의 최소 44px 조작 영역을 확인한다.

구성원 등록·수정은 하나의 카드 폼으로 제공하며 항목 간 `--space-4`(16px), 저장 동작 앞 `--space-5`(20px)를 유지한다. 기본 정보·생일·회비·계정 안내를 각각 카드로 분리하지 않는다. 생년월일은 출생연도 입력과 양력/음력 월·일 선택 달력으로 제공하며 선택 후 닫기, Esc 닫기와 포커스 복귀, 화살표 이동을 지원한다. 라벨을 포함한 선택 상자에는 명확한 접근성 이름을 부여하며, 320px에서는 입력을 한 열로 재배치한다. 월 회비는 총괄에게만 입력을 제공하고 총무에게는 설정 권한 안내를 표시한다.

구성원별 납부 현황은 월 회비(금액)와 납부일(조회 월 공통 마감일)을 별도 열로 제공한다. 모바일 카드도 독립 라벨을 유지하며, 날짜는 서버가 계산한 해당 월의 YYYY-MM-DD를 표시한다. 미설정은 미설정으로 표시하고, 실제 입금일과 혼동하지 않도록 표 위에 기준을 안내한다.

### 회비 현황 위젯
미확인 인원·금액을 요약 카드로 강조하고, 납부 진행은 회비가 설정된 구성원 중 납부 완료 인원으로 표시한다. 미설정은 분모에서 제외하고 별도 안내한다. 구성원 상태는 색과 텍스트 배지를 함께 제공하며, 자료 부족을 기한 초과로 표현하지 않는다. 위젯 폭이 좁아지면 금액·요청 버튼을 다음 줄로 정렬한다.


## 문의·이슈 상태 색상
대시보드 상태 카드와 문의 목록·상세·최근 문의의 배지는 동일한 색상 규칙을 사용한다. 접수는 info(파랑), 확인 중은 progress(보라), 추가 확인 필요는 warning(노랑/주황), 해결은 success(초록)로 표시한다. 배경/글자/테두리를 함께 구분하되 상태 문구를 항상 유지한다. progress의 라이트/다크 팔레트는 tokens.json과 CSS에 함께 정의하고 글자/배경 대비 4.5:1 이상을 검사한다. 카드의 기존 링크·키보드 포커스 동작은 유지한다.

### 사이드바 메뉴 상태
메뉴 목적별 아이콘을 구분한다(가족: 구성원, 관리할 일: 클립보드, 문서: 폴더, 권한: 방패). 현재 페이지는 배경·색·표식으로, 키보드 포커스는 3px 내부 테두리(offset -3px)로 구분한다. 스크롤 탐색 영역은 스크롤바 공간과 8px 안쪽 여백을 확보하여 표시가 잘리지 않게 한다.
