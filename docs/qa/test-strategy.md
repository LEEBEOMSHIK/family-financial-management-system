# 검증 전략과 인수 시나리오

제품 테스트는 아직 구현되지 않았다. 아래는 구현 담당자가 만들어야 할 기준이다. 이번 문서 묶음의 실행 검증은 docs/verification.md에 따로 기록한다.

## 계층

- 단위: 정책 판정, 정수 금액, 상태 전이, 날짜 계산, 중복 후보 분류. 고정 clock와 합성 fixture.
- 통합: 실제 PostgreSQL 제약/잠금/롤백/RLS, API 세션/CSRF, 객체 스토리지 권한, outbox 재처리.
- 계약: 은행/파일/알림 adapter가 같은 표준 오류·결과·지원 기능을 반환하는지 검증.
- E2E: 회원·총무·감사 계정으로 초대→지출 요청→승인→송금 기록→파일 대사→감사까지.
- UX/a11y: 키보드·포커스·확대·모바일·스크린리더, 대표 텍스트 대비, 오류 복구.

## 릴리스 차단 기준

권한 누출/금액 불일치/원장 중복/증빙 손실/잘못된 수신자/규정 없는 공식 투표는 한 건이라도 차단한다. 테스트 커버리지 수치가 이런 실패를 상쇄하지 않는다. 은행·카카오 실계정 검증 전 관련 feature flag는 비활성으로 유지한다. 구현되지 않은 기능은 숨김/명확한 안내로 처리하고 완료라고 표기하지 않는다.

테스트 fixture는 최소 두 가족·회원 3역할·임기 경계·같은 금액 두 거래·취소 지급·미대사 지급·서로 다른 ACL 문서·과거 정책을 포함한다. 운영 원본을 익명화했다고 임의로 넣지 말고 합성 자료를 우선한다.
