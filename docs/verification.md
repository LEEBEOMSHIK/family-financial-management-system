## 독립 설계 검토와 반영

구현을 맡지 않은 별도 검토자가 문서만으로 계획할 때 중요한 계약 충돌을 확인했다.

1. 정책 버전 변경으로 기본 회비가 중복 부과될 수 있는 키 구조 → 정책 버전과 독립된 obligation_key, 원부과 연결 조정으로 보완.
2. 승인 개정 후 구 지급·알림이 남는 문제 → approval_revision 결합, 원자적 superseded/취소, 재승인 연쇄를 추가.
3. accepted/unknown 알림이 일정·수신자 변경으로 다시 전송될 수 있는 문제 → 개정 간 공통 delivery_slot과 보류 규칙 추가.

설정, T27~T29 인수 시나리오, P2~P4 구현 계획에 반영했다. 검토자가 해당 세 항목의 수정을 재확인했고 그 재검토 범위에서 남은 중대한 충돌은 없었다. 이는 전체 제품 코드 리뷰나 실제 동작 검증이 아니다.

## 미실행·한계

- Next.js/React 예제의 전체 앱 typecheck/build/runtime 테스트: 실행 앱과 잠금 파일이 없으므로 미실행.
- FastAPI/PostgreSQL/RBAC/원장/알림 로직 테스트: 설계만 있으며 제품 구현 전이므로 미실행.
- 카카오뱅크 실계좌/API, 실제 은행 엑셀 서식, 카카오 계약/템플릿/수신 검증: 미실행.
- 운영규정 원문 대조, 승인권자·회비액·임기·정족수·보관기간 확정: 원문 미확보로 미실행.
- 브라우저 시각 검토: 로컬 HTTP 접근은 환경의 소켓 접근 제한으로 실패했고 직접 파일 URL은 브라우저 보안 정책상 허용되지 않았다. 이를 우회하지 않았다. 데스크톱·375px iframe 검토용 HTML은 제공하지만 **렌더링을 확인했다고 주장하지 않는다**.
- 전체 키보드/스크린리더/확대/반응형 접근성 검증, 운영 Docker build/배포/복원: 미실행.
