# 권한 매트릭스와 인수인계

상태: **역할 3개와 권한 관리 주체, 출금 요청 1인 결재 CONFIRMED (2026-10-24)**. 사용자가 일반사용자·총무·총괄관리자로 구분하고 총괄관리자만 권한을 관리하도록 지정했다. 출금 승인 규칙은 아래 후속 확정 사항을 따르며, 나머지 미확정 업무 조건은 운영규정 확인 전이다.

## 현재 기준

2026-10-24 후속 확정: 총무 또는 총괄관리자 1명이 출금 요청을 승인·반려한다. 총무가 제출한 요청은 총괄관리자가 처리한다. 자기 처리 금지는 유지한다. 실제 은행 송금은 총무가 별도로 수행한다. 요청 당시 또는 처리 시점에 총무 역할이 있으면 총괄관리자 전용 처리이며, 처리자의 유효 권한은 요청 시점 서버에서 확인한다. 현재 계정·역할은 PostgreSQL을 사용하며 아래 JSON 개발 저장소 및 과거 권한 표는 이전 설계 기록이다. [현재 구현 기록](../plans/accounts-evidence.md).

| 역할 | 식별자 | 범위 |
| --- | --- | --- |
| 일반사용자 | member | 공통 조회·설정, 공개된 모임 자료 조회 |
| 총무 | treasurer | 공통 기능 + 회계 운영·파일 관리. 권한 관리 불가 |
| 총괄관리자 | super_admin | 공통·관리 기능 + 구성원의 역할 부여·변경·회수 |

총무·총괄관리자의 파일 관리 세부 범위는 R20의 제안 설계이며, 확정된 핵심은 3역할과 총괄관리자의 권한 관리 독점이다. 총괄관리자도 같은 가족 범위·요청 시점 유효 권한·업무 정책 검증을 거친다. 총괄관리자라는 이유로 지출 자기 승인·확정 원장 수정·자동 송금을 허용하지 않는다.

권한 관리 메뉴는 총괄관리자에게만 표시하고 서버 API에서도 동일하게 검증한다. 변경 대상, 변경 전후 역할, 수행자, 적용 시각·근거를 이력으로 보존한다. 기존 세션에서도 다음 요청부터 현재 권한으로 재판정한다. 최초 총괄관리자 지정·마지막 총괄관리자 해제 방지·복구 절차는 별도 구현 기준으로 정하며 공개 회원가입으로 총괄관리자를 부여하지 않는다.

감사는 별도의 네 번째 제품 역할로 만들지 않는다. 감사 업무·승인 담당의 배정은 규정 확인 대상으로 남긴다. 기술 운영자는 제품 사용자 역할이 아닌 인프라 접근 주체이다.

현재 실행 앱은 3종 개발 계정, 총괄관리자 전용 /roles 화면과 조회·변경 API를 제공한다. 실행 스크립트는 역할 변경 이력을 로컬 JSON에 보존한다. 이는 단일 합성 가족의 개발용 저장소이며 운영 인증·DB 기반 권한 관리는 미구현이다. 아래 과거 매트릭스는 이 기준과 충돌할 경우 적용하지 않는다. [구현 인수인계](../plans/role-management.md).

## 판정 절차

1. 세션 유효성, 계정 잠금·탈퇴 확인.
2. 가족의 활성 membership와 요청 object의 family_id 확인.
3. 요청 시각 기준 role_assignment와 capability 확인.
4. 객체 소유권, 공개 등급, 업무 대상 범위 확인.
5. 상태·정책 버전·요청자와 승인자의 관계 확인.
6. 허용/거부의 actor/action/object/policy/request_id를 민감정보 없이 감사 기록.

권한이 없는 객체는 목록, 건수, 자동완성, AI 인용, 다운로드, 내보내기에서 모두 제외한다. 객체 존재 여부를 공개하면 안 되는 경우 404로 응답한다. 인증 없음은 401, 존재를 공개해도 되는 금지 행동은 403. UI에는 허용되는 다음 행동을 설명한다.

## 역할의 시간과 승계

`valid_from ≤ now < valid_to`인 역할만 유효하다. `valid_to=null`은 승인된 종료 미정 임기만 의미한다. 총무 한 명 정책은 제안이며 동시/공동 총무가 규정에 있으면 U06에서 결정한다. 그 전에는 총무가 0명 또는 2명 이상이면 외부 송금 알림을 차단하고 운영 예외로 표시한다.

새 총무 선임 시 임명 근거·시각을 저장하고 전임자의 역할을 종료한다. 서버 권한 캐시/세션을 무효화하고 새 총무에게 계좌 접근권·증빙 목록·미처리 지급·미대사 거래·알림 수신 연결을 확인시킨다. 비밀키를 인수인계 문서에 복사하지 않고 접근권을 교체한다. 이전 감사 로그의 actor는 변경하지 않는다.

알림은 발송 직전 현직 총무를 재조회한다. 이전 수신자를 고정한 큐는 무효화하고 새 assignment에 대해 재평가한다. 발송 직후 교체까지 원자적으로 통제할 수 없으므로 민감 내용을 최소화하고 최종 전달의 시각/수신 assignment를 보존한다. 새 총무에게 이미 발송된 알림을 자동 반복하지 않고 미처리 건을 인수인계 목록에 표시한다.

## 필수 권한 테스트

다른 가족 ID/다른 객체 ID 대입, 탈퇴 후 기존 세션, 임기 시작 직전·종료 정각, 오래된 역할 캐시, 일반 회원의 승인 엔드포인트 직접 호출, 증빙 URL 공유, export job 다운로드 후 권한 철회, 검색/RAG로 우회, 기술 운영자 권한과 업무 권한의 분리를 검증한다.
